# מקור יחיד ואישור חתימה נפרד — 24/11/2026

המסלול החדש מפיק מקור בפריוריטי פעם אחת ושומר אותו בנספח מסמך ממוחשב. ממשק החתימה מציג את אותם בתים שנשמרו בנספח. נתיב signature-copy נשמר לתאימות API אך אינו מפיק העתק ואינו מפעיל פרוצדורת הדפסה; הוא קורא את המקור הקיים בלבד. אם אין מקור, פתיחת החתימה נעצרת עד השלמת הכנתו במסלול ההתאוששות.

שם החותם, ציור החתימה ואישור מפורש לעיון בחשבונית נשמרים באישור PDF עצמאי הנוצר באפליקציה. האישור כולל IV, מספר חשבונית, לקוח, תאריך ושעה בשעון ישראל וב־UTC, גודל המקור ו־SHA-256 של המקור. זהו אישור חתימת לקוח, ולא חשבונית נוספת, מסמך מקור חלופי, אישור תשלום או אישור מסירת סחורה. הוא אינו מציג את חתימת הלקוח כחתימה אלקטרונית מאושרת.

הנספח החדש מתואר באמצעות ACK_ ומספר החשבונית. פתיחת אישור קיים תומכת גם בנספחי SIGNED_ הישנים. המקור אינו נכתב מחדש, וחתימתו הדיגיטלית אינה נערכת. בעת שמירת האישור נקרא המקור שוב מפריוריטי ונבדק שהוא זהה לקובץ שהוצג לחותם. לאחר העלאת האישור נקרא הנספח ונבדק שתוכנו זהה לקובץ שנוצר. כשל העלאה אינו מתיר העלאה כפולה ללא בדיקת הנספח הקיים.

יש לשמור בהעברת שרת את כל תיקיית data, ובפרט data/delivery ו־data/originals. נתוני תהליכים ישנים נשמרים; חתימה שהחלה בממשק הישן צריכה להיפתח מחדש על המקור לאחר רענון. לא נוצרו מסמכי ייצור לצורך בדיקת שינוי זה.

אימות: בדיקות תצוגת המקור המדויק, מקור שהוחלף בין עיון לחתימה, זיהוי לקוח ומסמך, הסכמה חסרה, שמירת אישור פעם אחת, הורדת אישורים ישנים וחדשים; אישור לדוגמה רונדר ונבדק חזותית בעברית ובשם מעורב. חבילת ההתקנה כוללת גם את התאוששות הסגירה לפי IV.
