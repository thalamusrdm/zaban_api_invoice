# מסכי מבנה להפקת חשבוניות בטלפון ובטאבלט

16.11.2026 · שלב תכנון המבנה, לפני עיצוב חזותי בסגנון Apple.

הלוח ממחיש את [תוכנית המוצר ומסלולי המשתמש](../product-ux-plan.he.md): ארבעת שלבי ההפקה, כניסה למסמכים קיימים ומצבי כשל. אפשר לעבור בין המסכים באמצעות תפריט התרחישים, או להתקדם בלחיצה על הפעולות במסכים עצמם.

## פתיחה

משורש הפרויקט:

```powershell
node docs/ux-wireframes/serve.cjs
```

פותחים את [לוח מסכי המבנה](http://127.0.0.1:18475/). אפשר גם לפתוח את `index.html` ישירות בדפדפן; שרת התצוגה הוא הדרך שנבדקה. לעצירה משתמשים ב־Ctrl+C. השרת מגיש קובצי תכנון בלבד ומאזין ב־localhost.

## מסלול הבדיקה המומלץ

1. בחרו ״כניסה״, פתחו חשבונית זהב וחפשו לקוח `900001`.
2. בחרו את הלקוח, שנו פרטי קשר בנתוני דמה ובדקו את נוסח כפתור ההמשך.
3. הזינו כמות ומחיר, הוסיפו או הסירו מוצר והמשיכו לבדיקה.
4. הפעילו ובטלו את בחירת המייל; ודאו שהנמען, התיאור וכפתור ההפקה עקביים.
5. המשיכו להתקדמות ההפקה ולבדיקת המצב, ואז לעיון ולחתימה.
6. בטלפון לחצו ״המשך לשם ולחתימה״, הזינו שם דמה וציירו. רק אז השמירה תהיה זמינה.
7. בחנו את תרחישי הכשל דרך תפריט הלוח, ועברו לטאבלט כדי להשוות את ארגון המידע.

כל תצוגת מכשיר היא עותק עצמאי. החלפת המסך בתפריט פותחת דוגמה חדשה בשתי התצוגות; ניווט בתוך מכשיר אחד אינו משנה את האחר. הקלט נשמר בזיכרון עד לרענון, ולא בדפדפן באופן מתמיד.

## הנחות שמוצגות בלי להכריע מדיניות עסקית

- מייל נדרש ומסומן משלוח כברירת מחדל, בהתאם למצב הקיים. הבחירה מוצגת כעת בבירור בשלב האישור.
- ״הצגת חשבונית ממתינה״ לאחר יציאה מחתימה היא המחשת מסלול אפשרי. זמינות השלמה מאוחרת במוצר תלויה בהרשאות ובמימוש שמירת מצב.
- חיפוש מסמכים, מצבי תת־פעולות ובדיקת מצב הם יכולות מוצעות, ולא טענה שהם קיימים כבר במערכת המותקנת.
- זהב מחושב במחיר ידני בש״ח לגרם; במסלולי דולר מוצגים מחיר בסיס ושער נעולים. שערי הדמה אינם שערים אמיתיים.
- תאריך הדוגמה הוא 16.11.2026. נציג, לקוח, מספרי מסמכים ומספרי זיהוי הם נתוני דמה.

## גבולות ההמחשה

אין גישה ל־Priority, לדואר או לנתוני לקוחות. שרת התצוגה אינו טוען `.env`, אינו מגיש קובצי מוצר או נתיבי API וחוסם בקשות כתיבה. CSP חוסם חיבורי רשת מתוך דפי ההמחשה. כפתורי הפקה, בדיקת מצב ושמירה משנים מצב מקומי בלבד. פעולות הורדה ועיון בהעתק חתום מציגות חיווי דמה, ללא מסמך כספי או נספח אמיתי.

ה״העתק״ הוא מבנה HTML לקריאת סדר המידע, ולא PDF מעוצב או תבנית מסמך חשבונאי. גם ציור חתימה בהמחשה אינו נשמר כחתימה של לקוח ואינו משמש לאישור מסמך. יש להשתמש בפרטי דמה בלבד.

לא שונו קובצי `public/`, השרת הראשי, תלויות המוצר או כללי ההפקה. כל התוצרים של שלב זה נמצאים בתיקיית התכנון הזאת.

## אימות שבוצע

- כל 20 המסכים נטענו בטלפון ובטאבלט; לא נמדדה גלילה אופקית במסכי המוצר באף אחד משני הגדלים.
- נבדקו בחירת לקוח, שינוי מייל והופעת ״שמירה והמשך״, עריכת כמות וחישוב הסיכום. בדוגמה: 3 גרם × 350 ש״ח = 1,050 לפני מע״מ ו־1,239 כולל מע״מ.
- לאחר עדכון שורת המוצר נבדקה הנחה גלויה של 10%: 700 ש״ח הפכו ל־630 לפני מע״מ ול־743.40 כולל מע״מ. הכמות, המחיר וההנחה נבדקו באותה שורה בטלפון ובטאבלט.
- נבדקו ביטול והפעלת בחירת המייל, התאמת נוסח הכפתור והמעבר להתקדמות ולחתימה.
- צוירה חתימת דמה, השמירה הופעלה לאחר שם וציור, ונצפה מסך הסיום.
- נבדקו מעבר משמירת חתימה שלא אומתה לניסיון ממוקד עם השם והציור, ובדיקת טיוטה לפני הצעת המשך סגירה.
- נבדקה טעינת שער מדומה ממצב חסר: מחיר 200 דולר ושער דמה 3.57 הציגו 714 ש״ח לפני מע״מ ו־842.52 כולל מע״מ. במצב שער חסר הוצג ״—״ במקום סכום.
- נבדק תחביר JavaScript. מעבר המסכים אינו מוכיח תקינות אינטגרציה, נגישות מלאה, הצגת PDF או פעולה על מכשיר פיזי.
