# מקור חשבונית דרך API

ב־22/10/2026 הותקנה והוכנה הפרוצדורה הנפרדת ZBAN_ORIGINALPDF בהתקנה הפעילה, באישור המשתמש. Priority אישרה שלא נמצאו שגיאות סינטקס ושהכנת התוכנית הסתיימה בהצלחה. פתיחת הפרוצדורה דרך ה־SDK נבדקה ובוטלה לפני הזנת חשבונית. לא הופק מסמך ולא נשלח מייל.

המקור עצמו טרם נבדק: המשתמש יפיק את החשבונית האמיתית הראשונה. אין להסיק מבדיקת סינטקס שהוגדרו חתימה דיגיטלית או קבלת מסמך ממוחשב אצל הלקוח.

## הפרדה מהעבודה הרגילה

- אין לפרוצדורה קישור לתפריט או מפרוצדורה קיימת; לא נוסף כפתור AINVOICES, ולא שונתה הפעלת סגירה, הדפסה או טריגר.
- הפרוצדורה בודקת SQL.ENV=zaban, משתמש API, ושהחשבונית בטיפול אותו משתמש. OWNERLOGIN הוא שדה לטיפול, ואינו הוכחה היסטורית מי יצר את החשבונית.
- אין בפרוצדורה פקודת מייל או פרמטר -AMAIL; אין שינוי של דגל PRINTED בקוד הפרטי. WWWSHOWAIV מבצעת את ניהול המסמך שלה.
- פרוצדורות עשויות להיות משותפות לחברות בהתקנה, אך זו מוגבלת בקוד לחברת zaban. אין לפרש זאת כשינוי ברישוי או בהרשאות המערכת.

## הממשק המקומי

סימון הורדת מקור מפעיל POST /api/invoices/original לאחר הסגירה. הורדת העתק משתמשת ב־GET /api/invoices/document הקיים. הסימון מופעל כברירת מחדל לצורך הבדיקה הראשונה; אפשר לבטלו. נשאר גם כפתור נפרד להורדת העתק. השרת המרוחק טרם עודכן.

רק חשבונית IN סופית בטיפול משתמש ה־API יכולה להיכנס למסלול. דרושה הגדרת CUSTOMERS.EDOCUMENTS=Y והרשאות חתימה קיימות; באישור מפורש סומן EDOCUMENTS=Y רק ללקוח 301100 ב־22/10/2026. חשבונית שכבר הודפסה נחסמת להפקת מקור נוסף.

data/originals/ מכילה קבצי PDF פרטיים ומצב הפקה לפי שרת/חברה/IV, מחוץ ל־Git ומחוץ לתיקיית public. חובה לשמר ולגבות אותה בעת עדכון/העברה של היישום. ניסיון נשמר לפני הקריאה לפריוריטי; אחרי timeout או תוצאה לא ברורה נחסמת הפקה חוזרת ונדרשת בדיקה ידנית. לאחר החזרת קישור נשמר הקישור, והורדה שנכשלה יכולה להוריד ממנו שוב. PDF שנשמר מוחזר בהורדות חוזרות ללא קריאה לפרוצדורה. היישום בודק כותרת PDF וסמן ByteRange; זו בדיקה מבנית לחתימה ואינה אימות קריפטוגרפי או אישור שהכותרת היא מקור. את הפלט הראשון נבדוק בפועל.

procedure.json ו־render.sql הם המקור שהותקן. קבצי draft נשמרו כהיסטוריית תכנון בלבד ואינם מיועדים להתקנה.
