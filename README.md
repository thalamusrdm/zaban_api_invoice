# ממשק הפקת חשבוניות מס — Priority

ממשק מקומי להפקת חשבוניות מס ב-Priority, משלוח מקור במייל והחתמת לקוח על העתק.
דורש Node.js 18 ומעלה והתקנת התלויות באמצעות `npm ci`.

## הפעלה

1. פותחים את הקובץ `.env` ומחליפים את `********` בסיסמה של משתמש ה-API.
2. מריצים:

   ```
   npm ci
   npm start
   ```

3. נכנסים בדפדפן ל: http://localhost:18473

ב-Windows אפשר גם להפעיל בלחיצה כפולה על `start-server.bat` לאחר התקנת התלויות. השרת רץ בחזית בחלון CMD ומציג את הלוגים. סגירת החלון מפסיקה את השרת; אפשר לעצור גם באמצעות Ctrl+C. אם השרת נעצר או נכשל, החלון נשאר פתוח להצגת ההודעה.

### חבילה ניידת לשרת Windows x64

`powershell -ExecutionPolicy Bypass -File scripts/build-portable.ps1 -IncludeConfig` בונה ZIP מקומי תחת `dist/` עם Node.js הרשמי (כולל אימות SHA256 ורישיון), תלויות לפי קובץ הנעילה וקובץ ההגדרות המקומי. אפשר להעביר `-NodeExecutable 'C:\Program Files\nodejs\node.exe'` כדי להשתמש בעותק מקומי: נבדקים חתימת OpenJS, גרסה וארכיטקטורה, ורישיון ההפצה מתקבל מהמקור הרשמי. בלי `-IncludeConfig` לא נכלל `.env` ויש להעתיקו מהשרת. הבנייה משתמשת ב־npm ובאינטרנט רק במחשב הבנייה; בשרת מחלצים הכול לתיקייה ומפעילים `start-server.bat`, ללא התקנה ושינוי PATH. ה־BAT מעדיף `runtime/node.exe` ופונה ל־Node המותקן רק אם אין עותק נייד. אין שירות רקע. בהחלפת גרסה יש לסגור קודם את החלון הישן ולשמור את `.env` של השרת. חבילה מוגדרת כוללת פרטי חיבור ולכן נשארת פרטית ומוחרגת מ־Git.

### הפקה, משלוח מקור וחתימה

לפני הפקה חובה לבחור לקוח, לבדוק כתובת מייל ולסמן במפורש „חשבונית דיגיטלית במייל”. כתובת קיימת נטענת מפריוריטי; כשאין כתובת הסוכן מזין אותה. לאחר בדיקת כרטיס הלקוח, הממשק שומר את המייל ואת הגדרת המסמך הממוחשב בפריוריטי, יוצר טיוטה וסוגר אותה לסופית. פריוריטי מתבקשת לשלוח מקור במייל במסלול המקורי שלה; לסוכן נפתח העתק נפרד לעיון ולחתימה על המסך. ההעתק עם עמוד החתימה מצורף לנספחי אותה חשבונית. [פרטי התהליך והתפעול](docs/digital-email-signature.md).

אישור פריוריטי לבקשת משלוח אינו אישור מסירה לתיבת הדואר. במקרה של תוצאה לא ודאית אין משלוח חוזר או הפקה חדשה אוטומטית. מסלולי ה־API הקודמים ליצירת טיוטה ולהורדת העתק נשמרו.

## מה יש בממשק

- חיווי חיבור לשרת Priority (ירוק/אדום) בראש הדף.
- חיפוש לקוח לפי שם או מספר (מתוך CUSTOMERS).
- בחירת סוג חשבונית: זהב, יהלומים או תכשיטים בשיבוץ יהלומי מעבדה.
- מחסן שולח, איתור, סוכן ומספר פנקס. מחסן/איתור/סוכן ריקים משאירים את הקביעה לפריוריטי; ההצעות מבוססות על חשבוניות אחרונות.
- טבלת שורות: מק״ט (ברירת מחדל 14 לזהב), כמות ביחידת המוצר (ברירת מחדל 1), מחיר ליחידה בדולרים, שער לש״ח והנחה לשורה. בחירת המטבע מוסתרת; המחיר והשער נעולים לעריכה.
- כל עמודות הטבלה מותאמות לרוחב המסך. סורק הפועל כמקלדת עם Enter בסיום יכול להזין מק״ט או ברקוד לשדה המק״ט. Enter מזהה מוצר מדויק לפי סוג החשבונית, פותח שורה חדשה ומעביר אליה את הסמן (או עובר לשורה הקיימת הבאה). סריקה ריקה, שגויה או דו־משמעית אינה מוסיפה שורה; Enter בתוך הטבלה אינו מפיק חשבונית.
- חיפוש המק״טים מוגבל לסיווג המתאים לסוג החשבונית בפריוריטי. בחירת מוצר ממלאת את מחירון הבסיס בדולרים; אם אין מחיר דולר תקין יש לעדכן את המוצר בפריוריטי לפני הפקה. בהחלפת סוג חשבונית עם מוצרים קיימים מתבקש אישור לניקוי המוצרים והמחירים, ופרטי הלקוח והחשבונית נשמרים.
- השער היציג לדולר מבנק ישראל נטען בבקשה אחת בפתיחת הממשק לפי תאריך החשבונית, ומשמש את כל שורות USD ו־$. שינוי תאריך טוען שער לתאריך החדש; חזרה לתאריך שכבר נטען משתמשת בשער שבזיכרון. נלקח השער האחרון שפורסם עד תאריך החשבונית, עם תאריך פרסום גלוי. במקרה של כשל או שער חסר מוצגת הודעה ונמנעת הפקה עד טעינת שער תקין.
- התיבה „השתמש בשער דולר מבנק ישראל” מסומנת כברירת מחדל. ביטול הסימון קורא שערי USD ו־$ בנפרד מפריוריטי, דרך מסך „מטבעות” ותת־מסך „שערי חליפין קודמים” ב־Web SDK. המקור והתאריך הם חלק ממפתח המטמון; אין מעבר אוטומטי למקור אחר במקרה של כשל. שיטת מחיר הזהב אינה משתנה בעקבות התיבה.
- בחשבונית זהב, מק״טים 14, 18 ו־F מקבלים מחיר לגרם מלוג מחירי הזהב `FZAB_GOLDPRICE`, דרך Web SDK בקריאה בלבד. נבחר העדכון האחרון עד סוף תאריך החשבונית, ולא מאוחר מזמן הטעינה. המחיר מעוגל לשתי ספרות לשדה PRICE ונעול לעריכה. המחירים נטענים פעם אחת לתאריך ומשמשים את כל השורות; חותמת העדכון מוצגת בממשק. המחיר הוא במטבע $ (דולר למכירות), לפי בחירת המשתמש. הצ׳קבוקס בוחר רק את שער הדולר לשקל, ומחיר הזהב עצמו תמיד מפריוריטי. במקרה של כשל אין תחליף ממחירון הבסיס למק״טים אלו. יתר מק״טי הזהב נשארים לפי מחירון הבסיס שלהם.
- ההנחה העליונה היא ברירת מחדל לשורות קיימות שטרם נערכו ולשורות חדשות. שינוי הנחה בשורה נשמר בנפרד ומחושב מהמחיר המלא שלה. אין הנחה נוספת ברמת החשבונית; הממשק שולח הנחת כותרת 0. מחירים והנחות אינם מועתקים מחשבוניות קודמות.
- תצוגה מקדימה של מע"מ 18% וסה"כ. הסכום הקובע הוא מה ש-Priority מחזיר.
- מניעת כפילויות: אם ממלאים "פרטים / מזהה הזמנה", המערכת בודקת לפני שליחה שלא קיימת כבר חשבונית עם אותו מזהה.
- רשימת 10 החשבוניות האחרונות שנוצרו על ידי משתמש ה-API.
- כל בקשה ותשובה נרשמות ל-`requests.log` (בלי הסיסמה).

הבסיס להשלמת השדות מתועד ב־[בדיקת שדות החשבוניות](docs/invoice-fields.md). להרצת בדיקות מיפוי וחישובים ללא כתיבה לפריוריטי: `npm test`.

## מגבלות שהתגלו בבדיקות (22/09/2026)

- ה-OData של Priority **לא תומך** בפונקציות `contains` / `startswith` (מחזיר 501). התחביר הנכון: `eq` עם כוכבית כתו-כל, למשל `CUSTDES eq '*לוג*'`.
- בהתחלה למשתמש `API` לא הייתה הרשאה למסך CUSTOMERS ("לא ניתן להפעיל API למסך זה"). ההרשאה נפתחה ב-22/09/2026 וחיפוש הלקוחות עובד. אם השגיאה חוזרת, הממשק עובר אוטומטית להזנת מספר לקוח ידנית.
- חשבונית בדיקה שנייה נוצרה בהצלחה דרך הממשק: **T59790** (לקוח 301755, ‏2 גרם × 350 ₪, סה"כ 826 ₪) — למחוק בפריוריטי.

## סגירת חשבונית (טיוטה → IN)

- PATCH על `STATDES` דרך OData נדחה: "התעודה זמנית... אפשר לסגור אותה בעזרת תוכניות מרשימת הפעולות של המסך".
- לכן הסגירה ממומשת דרך **Priority Web SDK** (`priority-web-sdk`, ראו `priority-sdk.js`): פתיחת טופס AINVOICES, סינון לפי IVNUM והרצת ההפעלה הישירה **`CLOSEANINVOICE`** ("סגירת החשבונית"). ה-SDK מתחבר עם אותם פרטי גישה של ה-API, בלי appid/appkey.
- את רשימת ההפעלות של הטופס אפשר לגלות דרך ה-SDK: `formStart('AINVOICES')` מחזיר אובייקט עם `activations` (שם מצאנו גם `CLOSEPRINTAIV` — סגירה+הדפסה, `IVSTORNO` — ביטול ועוד).
- שם הפרוצדורה ניתן לדריסה ב-`.env` עם `PRIORITY_CLOSE_PROC`.

## n8n

- `n8n/priority-invoice-workflow.json` — workflow מלא לייבוא (Webhook + הפעלה ידנית → ולידציה → תאריך לפי Asia/Jerusalem → בדיקת כפילות → יצירת טיוטה ב-AINVOICES → תשובות). סגירה ל-IN ו-PDF אפשריות רק דרך השרת המקומי (node כבוי בסוף ה-workflow).
- רשת: השם `iis.zaban-bechor.co.il` מתורגם ברשת המשרד ל-192.168.232.50 (פנימי), וב-DNS ציבורי ל-213.8.78.86. ההחרגה בחומת האש עבור שרת n8n ניתנה ל-213.8.78.84. כדי ש-n8n יעבוד: להחריג אותו גם על .86, או hosts `213.8.78.84 iis.zaban-bechor.co.il` בתוך סביבת הריצה של n8n (Docker: `extra_hosts`). לא לבטל אימות SSL.

## חשוב לדעת

- החשבונית נוצרת **כטיוטה** (מספר `T…`). סגירה לסופית נעשית ידנית במסך "חשבוניות מס" בפריוריטי.
- החלפת סביבה: `PRIORITY_COMPANY` ב-`.env`. קודי חברות: ייצור = `zaban` ("צבאן בכור תכשיטים בע\"מ"), טסט ישן = `zabcopy` (העתק מ-2020, אי אפשר לסגור בו חשבוניות — אין תבניות מספור ל-2026), טסט חדש = `zabant` ("צבאן טסט 040626"). ב-23/09/2026 הועבר ל-`zaban`.
- בחברת הטסט `zabcopy` הסגירה נחסמה בשרשרת: תקופה כספית סגורה (נפתחה עד 9/2026) ואז "בעית רצף במספרי החשבוניות" (סדרת מספור IN לא הוכנה ל-2026).
- אם יש timeout בלי תשובה — ה-IP של המחשב לא מאושר בחומת האש של שרת Priority (לא בעיה בקוד).
- התאריך נבנה תמיד באזור הזמן Asia/Jerusalem כולל שעון קיץ/חורף.
