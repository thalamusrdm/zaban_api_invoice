# ממשק הפקת חשבוניות מס — Priority

ממשק לוקאלי קל להפקת חשבוניות מס (טיוטות) ב-Priority דרך ה-OData API.
דורש Node.js 18 ומעלה והתקנת התלויות באמצעות `npm ci`.

## הפעלה

1. פותחים את הקובץ `.env` ומחליפים את `********` בסיסמה של משתמש ה-API.
2. מריצים:

   ```
   npm ci
   npm start
   ```

3. נכנסים בדפדפן ל: http://localhost:3600

## מה יש בממשק

- חיווי חיבור לשרת Priority (ירוק/אדום) בראש הדף.
- חיפוש לקוח לפי שם או מספר (מתוך CUSTOMERS).
- טבלת שורות: מק"ט (קראט, ברירת מחדל 14), כמות בגרם, מחיר לגרם לפני מע"מ.
- תצוגה מקדימה של מע"מ 18% וסה"כ. הסכום הקובע הוא מה ש-Priority מחזיר.
- מניעת כפילויות: אם ממלאים "פרטים / מזהה הזמנה", המערכת בודקת לפני שליחה שלא קיימת כבר חשבונית עם אותו מזהה.
- רשימת 10 החשבוניות האחרונות שנוצרו על ידי משתמש ה-API.
- כל בקשה ותשובה נרשמות ל-`requests.log` (בלי הסיסמה).

## מגבלות שהתגלו בבדיקות (22/09/2026)

- ה-OData של Priority **לא תומך** בפונקציות `contains` / `startswith` (מחזיר 501). התחביר הנכון: `eq` עם כוכבית כתו-כל, למשל `CUSTDES eq '*לוג*'`.
- בהתחלה למשתמש `API` לא הייתה הרשאה למסך CUSTOMERS ("לא ניתן להפעיל API למסך זה"). ההרשאה נפתחה ב-22/09/2026 וחיפוש הלקוחות עובד. אם השגיאה חוזרת, הממשק עובר אוטומטית להזנת מספר לקוח ידנית.
- חשבונית בדיקה שנייה נוצרה בהצלחה דרך הממשק: **T59790** (לקוח 301755, ‏2 גרם × 350 ₪, סה"כ 826 ₪) — למחוק בפריוריטי.

## סגירת חשבונית (טיוטה → IN)

- PATCH על `STATDES` דרך OData נדחה: "התעודה זמנית... אפשר לסגור אותה בעזרת תוכניות מרשימת הפעולות של המסך".
- לכן הסגירה ממומשת דרך **Priority Web SDK** (`priority-web-sdk`, ראו `priority-sdk.js`): פתיחת טופס AINVOICES, סינון לפי IVNUM והרצת ההפעלה הישירה **`CLOSEANINVOICE`** ("סגירת החשבונית"). ה-SDK מתחבר עם אותם פרטי גישה של ה-API, בלי appid/appkey.
- את רשימת ההפעלות של הטופס אפשר לגלות דרך ה-SDK: `formStart('AINVOICES')` מחזיר אובייקט עם `activations` (שם מצאנו גם `CLOSEPRINTAIV` — סגירה+הדפסה, `IVSTORNO` — ביטול ועוד).
- שם הפרוצדורה ניתן לדריסה ב-`.env` עם `PRIORITY_CLOSE_PROC`.

## n8n

- `n8n/priority-invoice-workflow.json` — workflow מלא לייבוא (Webhook + הפעלה ידנית → ולידציה → תאריך לפי Asia/Jerusalem → בדיקת כפילות → יצירת טיוטה ב-AINVOICES → תשובות). סגירה ל-IN ו-PDF אפשריות רק דרך השרת המקומי (node כבוי בסוף ה-workflow).
- רשת: השם `iis.zaban-bechor.co.il` מתורגם ברשת המשרד ל-192.168.232.50 (פנימי), וב-DNS ציבורי ל-213.8.78.86. ההחרגה בחומת האש עבור שרת n8n ניתנה ל-213.8.78.84. כדי ש-n8n יעבוד: להחריג אותו גם על .86, או hosts `213.8.78.84 iis.zaban-bechor.co.il` בתוך סביבת הריצה של n8n (Docker: `extra_hosts`). לא לבטל אימות SSL.

## חשוב לדעת

- החשבונית נוצרת **כטיוטה** (מספר `T…`). סגירה לסופית נעשית ידנית במסך "חשבוניות מס" בפריוריטי.
- החלפת סביבה: `PRIORITY_COMPANY` ב-`.env`. קודי חברות: ייצור = `zaban` ("צבאן בכור תכשיטים בע\"מ"), טסט ישן = `zabcopy` (העתק מ-2020, אי אפשר לסגור בו חשבוניות — אין תבניות מספור ל-2026), טסט חדש = `zabant` ("צבאן טסט 040626"). ב-23/09/2026 הועבר ל-`zaban`.
- בחברת הטסט `zabcopy` הסגירה נחסמה בשרשרת: תקופה כספית סגורה (נפתחה עד 9/2026) ואז "בעית רצף במספרי החשבוניות" (סדרת מספור IN לא הוכנה ל-2026).
- אם יש timeout בלי תשובה — ה-IP של המחשב לא מאושר בחומת האש של שרת Priority (לא בעיה בקוד).
- התאריך נבנה תמיד באזור הזמן Asia/Jerusalem כולל שעון קיץ/חורף.
